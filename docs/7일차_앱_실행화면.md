# 7일차 앱 실행 화면

> 과제: 프론트 템플릿 코드(`static/`)에 API를 연결하고, `fastapi run app/main.py`로 실행한 화면을 endpoint별로 정리한다.
>
> 팀원별 담당
> - 엄태은: 실행 방법, API 연결 구조, 토큰 재발급, 진료기록 목록·상세, AI 예측
> - 김민준: 회원가입, 로그인, 로그아웃, 마이페이지(조회·수정·비밀번호 변경·탈퇴)
> - 장성은: 환자 등록·삭제, 진료기록 등록
> - 여현지: 환자 목록·상세·수정, 관리자 회원 관리
>
> 캡처 규칙: 테스트 계정·공개 샘플 X-ray만 사용, 토큰·비밀번호가 보이면 가리기. 이미지는 `docs/images/day7/` 에 `번호_기능.png` 이름으로 저장.

---

## 0. 실행 방법과 화면 ↔ API 대응 (담당: 엄태은)

### 0-1. 실행

```powershell
git switch develop
git pull origin develop
uv sync
fastapi run app/main.py
```

- 브라우저에서 `http://127.0.0.1:8000/` 으로 접속한다. (Windows에서는 `0.0.0.0` 대신 `127.0.0.1`)
- 다른 프로그램이 8000번 포트를 쓰고 있으면 `fastapi run app/main.py --port 8001` 로 실행하고 `http://127.0.0.1:8001/` 로 접속한다.

### 0-2. 화면이 API를 부르는 방식

<!--
- static/apis.js 의 request(): API_BASE(/api/v1) + 주소, Authorization: Bearer 토큰 자동 첨부
- 401이면 /users/refresh(쿠키)로 새 토큰을 받아 원래 요청을 다시 보냄, 실패하면 로그아웃
- 에러 응답의 detail을 알림창으로 보여 줌 (422 배열은 msg만 모아서)
-->

### 0-3. 화면 ↔ API 대응표

| # | 화면 | 동작 | 메서드·주소 | 담당 |
|---|---|---|---|---|
| 1 | 회원가입 | 가입 버튼 | `POST /api/v1/users/signup` | 김민준 |
| 2 | 로그인 | 로그인 버튼 → 내 정보 | `POST /api/v1/users/login`, `GET /api/v1/users/me` | 김민준 |
| 3 | (자동) | 토큰 만료 시 재발급 | `POST /api/v1/users/refresh` | 엄태은 |
| 4 | 상단 메뉴 | 로그아웃 | `POST /api/v1/users/logout` | 김민준 |
| 5 | 마이페이지 | 정보 수정 / 비밀번호 변경 / 탈퇴 | `PATCH /users/me`, `PATCH /users/me/password`, `DELETE /users/me` | 김민준 |
| 6 | 회원 관리(관리자) | 목록·검색 / 권한 변경 | `GET /api/v1/admin/users`, `PATCH /api/v1/admin/users/role` | 여현지 |
| 7 | 환자 등록 | 등록 버튼 | `POST /api/v1/patients` | 장성은 |
| 8 | 환자 목록 | 목록·검색 | `GET /api/v1/patients` | 여현지 |
| 9 | 환자 상세 | 상세보기 / 정보 수정 | `GET /api/v1/patients/{id}`, `PATCH /api/v1/patients/{id}` | 여현지 |
| 10 | 환자 상세 | 삭제 | `DELETE /api/v1/patients/{id}` | 장성은 |
| 11 | 진료기록 등록 | 등록 버튼 (X-ray 업로드) | `POST /api/v1/medical-records` | 장성은 |
| 12 | 환자 상세 | 진료기록 목록 | `GET /api/v1/patients/{id}/medical-records` | 엄태은 |
| 13 | 진료기록 상세 | 상세 / AI 예측 결과보기 / 예측 결과 목록 | `GET /medical-records/{id}`, `POST …/predict`, `GET …/analyses` | 엄태은 |

## 1. 회원가입 (담당: 김민준)

<!--
- 화면: signup / API: POST /api/v1/users/signup
- 캡처: 입력 화면, 가입 성공 알림, (선택) 비밀번호 규칙 위반 알림
- 설명: 보내는 값(email, password, name, department, gender, phone_number), 성공 시 이동 화면
-->

## 2. 로그인 · 로그아웃 (담당: 김민준)

<!--
- 로그인: POST /api/v1/users/login (폼 username·password) → 응답 access_token 저장 → GET /api/v1/users/me 로 상단 이름(부서) 표시
- 대기자(pending)는 홈으로, staff 이상은 환자 목록으로 이동
- 로그아웃: POST /api/v1/users/logout → 쿠키 삭제, 로그인 화면으로
-->

## 3. 토큰 재발급 (담당: 엄태은)

<!--
- 액세스 토큰(30분) 만료 후 요청 → 401 → apis.js가 POST /api/v1/users/refresh 자동 호출 → 원래 요청 재시도
- 캡처: 개발자 도구 Network 탭에서 refresh 호출 확인 (토큰 값은 가리기)
-->

## 4. 마이페이지 (담당: 김민준)

<!--
- 조회: GET /api/v1/users/me / 정보 수정: PATCH /api/v1/users/me (부서·휴대폰)
- 비밀번호 변경: PATCH /api/v1/users/me/password / 회원 탈퇴: DELETE /api/v1/users/me (테스트 계정으로만!)
-->

## 5. 회원 관리 (관리자, 담당: 여현지)

<!--
- 목록·검색: GET /api/v1/admin/users?query=&department=
- 권한 변경: PATCH /api/v1/admin/users/role {user_id, new_role} → 대기자를 staff로 승인
- 관리자 본인 행은 변경 불가(400)
-->

## 6. 환자 등록 · 삭제 (담당: 장성은)

<!--
- 등록: POST /api/v1/patients (의료인만) → 목록 맨 위에 표시
- 삭제: DELETE /api/v1/patients/{id} → 확인 후 목록에서 사라짐 (진료기록·X-ray 파일도 삭제)
-->

## 7. 환자 목록 · 상세 · 수정 (담당: 여현지)

<!--
- 목록·검색: GET /api/v1/patients?name=&gender=&min_age=&max_age=
- 상세: GET /api/v1/patients/{id} / 수정: PATCH /api/v1/patients/{id} (이름·연락처)
-->

## 8. 진료기록 등록 (담당: 장성은)

<!--
- POST /api/v1/medical-records (form-data: patient_id, chart_number, symptoms, xray_image)
- 캡처: 입력 + 이미지 미리보기, 등록 후 환자 상세의 목록
-->

## 9. 진료기록 목록 · 상세 · AI 예측 (담당: 엄태은)

<!--
- 목록: GET /api/v1/patients/{id}/medical-records (증상 100자 요약)
- 상세: GET /api/v1/medical-records/{id} (X-ray 이미지 표시)
- AI 예측 결과보기: POST /api/v1/medical-records/{id}/predict → 결과 표 (Positive/Negative, Confidence, 모델)
- 예측 결과 목록: GET /api/v1/medical-records/{id}/analyses, 다시 눌러도 줄이 늘지 않음(재사용)
-->
