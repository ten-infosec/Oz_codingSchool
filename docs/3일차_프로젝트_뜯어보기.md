### 2-2. `app/models/` (담당: 여현지)

- 역할: DB 테이블을 Python 클래스로 정의 (SQLAlchemy model 정의). 클래스 하나가 테이블 하나에 대응하며, 컬럼 타입, 제약조건, 테이블 간 관계를 선언
- 들어가는 것
    - Base를 상속한 SQLAlchemy 모델 클래스
    - 컬럼(mapped_column), 기본키/외래키 등의 제약
    - 테이블 간 관계

- 예시
```python
app/models/user.py

from sqlalchemy.orm import Mapped, mapped_column
from app.db.database import Base

class User(Base):
    __tablename__ = "users"

    id: Mapped[int] = mapped_column(primary_key=True, index=True)
    username: Mapped[str] = mapped_column(unique=True, index=True)
    password_hash: Mapped[str]
```

### 2-3. `app/repositories/` (담당: 여현지)

- 역할: DB와 직접 대화하는 유일한 계층. SQLAlchemy Session을 받아 조회·생성·수정·삭제(CRUD) 쿼리 실행
- 들어가는 것
    - select, add, commit, delete 같은 DB 작업 함수
    - 조건 조회 (`get_by_id`, `get_by_email`, `list_all`) 등

- 예시
```python
# app/repositories/user_repository.py

from sqlalchemy import select
from sqlalchemy.orm import Session

from app.models.user import User


def get_by_username(db: Session, username: str) -> User | None:
    return db.scalar(select(User).where(User.username == username))


def create(db: Session, username: str, password_hash: str) -> User:
    user = User(username=username, password_hash=password_hash)
    db.add(user)
    db.commit()
    db.refresh(user)
    return user
```

### 2-4. `app/schemas/` (담당: 여현지)

- 역할: API로 주고받는 데이터의 형태와 검증 규칙을 정의. 요청 바디를 자동 검증, 응답을 원하는 형태로 직렬화, Swagger 문서(/docs)도 스키마 기반으로 생성
- 들어가는 것
    - 요청용 스키마 (UserCreate, UserUpdate)
    - 응답용 스키마 (UserResponse)
    - 필드 타입, 길이 제한, 이메일 형식 등 검증 규칙

- 예시
```python
# app/schemas/user.py

from pydantic import BaseModel, ConfigDict


class UserCreate(BaseModel):
    username: str
    password: str


class UserResponse(BaseModel):
    id: int
    username: str

    model_config = ConfigDict(from_attributes=True)
```

### 2-5. `app/services/` (담당: 여현지)

- 역할: 프로젝트의 규칙과 흐름을 처리. "이메일이 중복되면 가입할 수 없다.", "비밀번호는 해시해서 저장한다."처럼 서비스가 어떻게 동작해야 하는지를 코드로 표현
- 들어가는 것
    - 여러 repository 호출을 조합하는 로직
    - 중복 검사, 권한 확인, 계산, 데이터 가공
    - 비즈니스 규칙 위반 시 예외 발생 (HTTPException) 등

- 예시
```python
# app/services/user_service.py

from fastapi import HTTPException, status
from sqlalchemy.orm import Session

from app.core.security import hash_password
from app.repositories import user_repository
from app.schemas.user import UserCreate


def create_user(db: Session, user: UserCreate):
    # 비즈니스 규칙: username 중복 불가
    if user_repository.get_by_username(db, user.username):
        raise HTTPException(
            status_code=status.HTTP_400_BAD_REQUEST,
            detail="이미 사용 중인 username입니다.",
        )
    return user_repository.create(db, user.username, hash_password(user.password))
```

### 2-6. `app/apis/` (담당: 여현지)

- 역할: 클라이언트의 HTTP 요청이 가장 먼저 도착하는 곳. URL 경로와 HTTP 메서드(GET, POST 등)를 정의하고, 요청을 받아 services를 호출한 뒤 결과를 응답으로 돌려줌
- 들어가는 것
    - APIRouter로 만든 엔드포인트 함수
    - 경로, 메서드, 상태 코드, 응답 모델(response_model) 설정
    - Depends를 이용한 의존성 주입 (DB 세션, 인증 등)

- 예시
```python
# app/apis/users.py

from fastapi import APIRouter, Depends
from sqlalchemy.orm import Session

from app.core.db.databases import get_db  # 실제 위치에 맞게 수정
from app.schemas.user import UserCreate, UserResponse
from app.services import user_service

router = APIRouter(prefix="/users", tags=["users"])


@router.post("/", response_model=UserResponse)
def create_new_user(user: UserCreate, db: Session = Depends(get_db)):
    return user_service.create_user(db, user)
```

### 2-7. 요청 처리 흐름 (담당: 여현지)

```text
클라이언트 요청
   ↓
apis/           경로(URL) 정의, 요청 수신, schemas로 입력 검증
   ↓
services/       비즈니스 로직 처리
   ↓
repositories/   DB 쿼리 실행 (CRUD)
   ↓
models/         DB 테이블 구조 (SQLAlchemy ORM)
   ↓
DB
```
- 응답은 반대 방향으로 돌아오며, 마지막에 schemas/의 응답 스키마로 변환되어 클라이언트에 전달
