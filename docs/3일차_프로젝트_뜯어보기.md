## 2. 디렉터리별 역할과 작성할 내용

### 2-1. `app/core/` (담당: 김민준)


#### 1. 폴더의 역할

`app/core/`는 애플리케이션 전체에서 공통으로 사용하는 핵심 설정과 기능을 관리하는 디렉터리이다.

데이터베이스 연결이나 환경변수 설정처럼 여러 기능에서 공통으로 필요한 코드를 모아 관리한다.

#### 2. 주요 파일 및 하위 폴더

- `__init__.py`: 해당 디렉터리를 Python 패키지로 구성할 때 사용하는 파일이다.
- `config.py`: 환경변수 및 데이터베이스 연결 설정값을 관리한다.
- `db/`: 데이터베이스 연결과 SQLAlchemy 공통 모델 구성에 필요한 기능을 관리한다.

#### 3. core 폴더를 분리하는 이유

공통 설정과 기능을 한곳에서 관리하면 코드 중복을 줄일 수 있다.

또한 데이터베이스 접속 정보가 변경되더라도 관련 설정을 중앙에서 관리할 수 있어 유지보수에 유리하다.

**정리:** `app/core/`는 프로젝트의 여러 모듈이 공통으로 사용하는 설정과 기반 기능을 관리하는 디렉터리이다.

### 3-2. `app/core/config.py` (담당: 김민준)
#### 1. 파일의 역할

`config.py`는 프로젝트에서 사용하는 데이터베이스 연결 설정을 한곳에서 관리하는 파일이다.

`pydantic-settings`의 `BaseSettings`를 사용하여 환경변수와 기본 설정값을 읽고, 다른 모듈에서도 동일한 설정을 사용할 수 있도록 한다.

#### 2. 주요 코드 구조

```python
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    DB_USER: str = "root"
    DB_PASSWORD: str = "password1234"
    DB_HOST: str = "localhost"
    DB_PORT: str = "3306"
    DB_NAME: str = "ai_health"

    model_config = {
        "env_file": ".env",
        "extra": "ignore"
    }

settings = Settings()
```

**주요 코드 설명**

- `BaseSettings`: 환경변수와 기본 설정값을 관리한다.
- `DB_USER`: 데이터베이스 사용자 계정
- `DB_PASSWORD`: 데이터베이스 접속 비밀번호
- `DB_HOST`: 데이터베이스 서버 주소
- `DB_PORT`: 데이터베이스 접속 포트
- `DB_NAME`: 데이터베이스 이름
- `env_file`: `.env` 파일에서 설정을 읽도록 지정한다.
- `extra="ignore"`: 정의하지 않은 추가 설정 항목을 무시한다.
- `settings = Settings()`: 설정 객체를 생성하여 다른 모듈에서 재사용한다.

#### 3. `.env`와 `.env.example`의 차이

`.env.example`은 프로젝트 실행에 필요한 환경변수의 이름과 예시값을 제공하는 파일이다.

`.env`는 개발자가 자신의 컴퓨터에서 사용할 실제 환경변수를 저장하는 파일이다.

`config.py`는 `.env`에 정의된 설정값을 읽을 수 있으며, 해당 값이 없으면 클래스의 기본값을 사용한다. 동일한 환경변수가 실행 환경에도 설정되어 있다면 일반적으로 실행 환경의 값이 우선한다.

현재 `.env.example`에는 `DB_ROOT_PASSWORD`가 있지만, `Settings` 클래스에는 해당 항목이 정의되어 있지 않다. 별도 Docker 설정에서 사용되는지 확인할 필요가 있다.

#### 4. 주의사항

- 실제 비밀번호나 API 키가 들어 있는 `.env` 파일은 GitHub에 업로드하지 않는다.
- `.env.example`에는 실제 비밀번호가 아닌 예시값을 사용한다.
- 운영 환경에서는 중요한 인증 정보를 코드에 직접 작성하지 않고 안전하게 관리한다.

**정리:** `config.py`는 프로젝트 설정을 중앙에서 관리하고, `.env`는 환경마다 다른 설정값을 적용할 수 있도록 한다.

### 3-3. `pyproject.toml` (담당: 김민준)

#### 1. 파일의 역할

`pyproject.toml`은 Python 프로젝트의 기본 정보, Python 버전, 라이브러리 의존성을 정의하는 설정 파일이다.

프로젝트를 실행하는 데 필요한 패키지를 한곳에서 관리하며, 팀원들이 동일한 개발 환경을 구성하는 데 사용한다.

#### 2. 프로젝트 기본 설정

현재 프로젝트의 `pyproject.toml`에는 다음 정보가 정의되어 있다.

```toml
[project]
name = "ai-health-web-assignment"
version = "0.1.0"
description = "Add your description here"
readme = "README.md"
requires-python = ">=3.13"
```

- `name`: 프로젝트 이름
- `version`: 프로젝트 버전
- `description`: 프로젝트 설명 (현재 기본 문구)
- `readme`: 프로젝트 설명 문서의 경로
- `requires-python`: Python 3.13 이상을 요구한다는 의미

프로젝트가 Python 3.13 이상을 요구하더라도 모든 상위 버전에서 라이브러리가 정상 작동한다는 뜻은 아니다. 실제 실습 환경에서는 Python 3.13을 사용하는 것이 적절하다.

#### 3. 주요 라이브러리와 역할

| 라이브러리 | 역할 |
|---|---|
| `fastapi[standard]` | REST API 서버 개발 및 실행 |
| `sqlalchemy[asyncio]` | 비동기 데이터베이스 작업과 ORM 모델 관리 |
| `alembic` | 데이터베이스 스키마 변경 및 마이그레이션 |
| `asyncmy` | Python과 MySQL 간 비동기 연결 |
| `pydantic-settings` | 환경변수 및 애플리케이션 설정 관리 |
| `cryptography` | 암호화 관련 기능 제공 |
| `uuid6` | UUID 생성 기능 제공 |

각 라이브러리의 버전 조건에 있는 `>=`는 해당 버전 이상을 허용한다는 의미이다.

#### 4. 개발 환경 구성

이 프로젝트는 `uv`를 사용하여 Python 의존성을 관리할 수 있다.

프로젝트 폴더에서 다음 명령어로 의존성을 설치한다.

```bash
uv sync --python 3.13 --locked
```

- `uv sync`: 프로젝트 의존성을 설치하고 가상환경을 동기화한다.
- `--python 3.13`: Python 3.13을 사용한다.
- `--locked`: 기존 잠금 파일을 변경하지 않고 의존성을 동기화한다.

이를 통해 팀원들이 프로젝트 실행에 필요한 패키지를 일관되게 설치할 수 있다.

#### 5. uv.lock과의 관계

`pyproject.toml`은 프로젝트가 요구하는 패키지와 버전 범위를 정의한다.

반면 `uv.lock`은 의존성 해결을 통해 선택된 구체적인 패키지 버전과 하위 의존성 정보를 기록한다.

따라서 두 파일을 함께 관리하면 팀원 간 개발 환경 차이를 줄일 수 있다.

**정리:** `pyproject.toml`은 프로젝트에 어떤 Python 버전과 라이브러리가 필요한지 정의하는 핵심 설정 파일이다.

### 3-4. `uv.lock` (담당: 김민준)

#### 1. 파일의 역할

`uv.lock`은 Python 패키지 관리 도구인 `uv`가 생성하는 잠금 파일(Lock File)이다.

프로젝트에서 사용하는 라이브러리의 구체적인 버전, 하위 의존성, 패키지 출처 등의 정보를 기록한다.

팀원들이 동일한 의존성 버전을 설치할 수 있도록 하여 개발 환경의 차이를 줄이는 역할을 한다.

#### 2. 주요 코드 구조

현재 프로젝트의 `uv.lock` 파일에는 다음과 같은 내용이 포함되어 있다.

```toml
version = 1
revision = 3
requires-python = ">=3.13"

[[package]]
name = "alembic"
version = "1.18.4"
source = { registry = "https://pypi.org/simple" }

- `version`: 잠금 파일 형식 버전
- `revision`: 잠금 파일 형식의 리비전
- `requires-python`: 프로젝트에서 요구하는 Python 버전 조건
- `[[package]]`: 개별 라이브러리의 정보
- `name`: 라이브러리 이름
- `version`: 실제 선택된 라이브러리 버전
- `source`: 패키지를 가져오는 출처
- `dependencies`: 해당 패키지가 필요로 하는 다른 라이브러리

#### 3. pyproject.toml과 uv.lock의 차이

| 구분 | pyproject.toml | uv.lock |
|---|---|---|
| 목적 | 프로젝트 요구사항 정의 | 구체적인 의존성 버전 기록 |
| 버전 | 허용 범위 지정 | 실제 선택된 버전 기록 |
| 수정 방식 | 개발자가 직접 관리 | uv가 자동 생성·갱신 |
| GitHub 관리 | 커밋 | 커밋 |
| 주요 역할 | 필요한 라이브러리 선언 | 설치 환경 재현 |

예를 들어 `pyproject.toml`에는 다음과 같이 작성되어 있다.

```toml
"alembic>=1.18.4"
```

반면 `uv.lock`에는 다음처럼 선택된 버전이 기록되어 있다.

```toml
name = "alembic"
version = "1.18.4"
```

즉, `pyproject.toml`은 어떤 버전이 허용되는지 정의하고, `uv.lock`은 실제 의존성 해결 결과를 기록한다.

#### 4. 주요 uv 명령어

```bash
uv sync --python 3.13 --locked
```

- `uv sync`: 잠금 파일을 기준으로 프로젝트 가상환경과 패키지를 동기화한다.
- `--python 3.13`: Python 3.13 인터프리터를 사용한다.
- `--locked`: 잠금 파일이 최신 상태인지 확인하고, 파일을 수정하지 않는다.

`uv.lock`은 수동으로 수정하지 않고, 의존성이 변경되면 uv 명령어를 통해 갱신하는 것이 적절하다.

#### 5. 팀 프로젝트에서의 중요성

팀원마다 다른 패키지 버전을 설치하면 동일한 코드에서도 실행 결과나 오류가 달라질 수 있다.

`uv.lock`을 GitHub에서 함께 관리하면 팀원들이 일관된 라이브러리 버전을 설치할 수 있다. 다만 운영체제 및 Python 버전 차이 등에 따라 실제 설치 구성에는 차이가 있을 수 있다.

**정리:** `pyproject.toml`이 필요한 패키지를 정의하는 파일이라면, `uv.lock`은 그 요구사항을 충족하도록 선택된 패키지 버전을 기록해 개발 환경을 재현하는 파일이다.
