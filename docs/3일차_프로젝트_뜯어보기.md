## 4. 데이터베이스 연결 설정: `app/core/db/databases.py` (담당: 장성은)

FastAPI 서버가 MySQL과 연결되도록 준비하는 파일이다.

### 4-1. DATABASE_URL 구성
```python
DATABASE_PREFIX = "mysql+asyncmy://"
DATABASE_URI = f"{settings.DB_USER}:{settings.DB_PASSWORD}@{settings.DB_HOST}:{settings.DB_PORT}/{settings.DB_NAME}"
DATABASE_URL = f"{DATABASE_PREFIX}{DATABASE_URI}"
```
- `mysql+asyncmy://` : MySQL을 쓰고, `asyncmy`(비동기 드라이버)로 연결한다는 뜻
- 아이디, 비밀번호, 주소, 포트, DB 이름은 `config.py`의 `settings`에서 가져온다
- `settings`는 `.env` 파일 값을 먼저 읽고, 없으면 `config.py`에 적힌 기본값을 쓴다
- 완성된 주소 예: `mysql+asyncmy://ozcoding:pw1234@localhost:3306/ai_health`

### 4-2. 엔진
```python
async_engine = create_async_engine(DATABASE_URL, echo=False, future=True)
```
- 서버와 DB를 잇는 연결 통로
- `echo=False` : 실행되는 SQL을 터미널에 출력하지 않음

### 4-3. 세션
```python
AsyncSessionLocal = async_sessionmaker(bind=async_engine, autoflush=False, expire_on_commit=False)
```
- 세션 : DB 작업 한 번(조회, 저장 등)을 처리하는 단위
- `AsyncSessionLocal` : 세션을 찍어내는 틀
- `autoflush=False` : 직접 commit하기 전엔 DB에 자동으로 보내지 않음
- `expire_on_commit=False` : commit한 뒤에도 객체 값을 그대로 쓸 수 있음

### 4-4. Base
```python
Base = declarative_base()
```
- 모든 DB 모델(테이블 클래스)이 물려받는 부모 클래스
- 모델이 Base를 상속하면 `Base.metadata`에 테이블 정보가 모이고, alembic이 이걸 보고 테이블을 만든다

### 4-5. async_get_db
```python
async def async_get_db() -> AsyncGenerator[AsyncSession, None]:
    async with AsyncSessionLocal() as db:
        yield db
```
- API가 실행될 때 세션을 하나 빌려주고, API가 끝나면 자동으로 닫는다
- API 함수에서 `Depends(async_get_db)`로 받아서 쓴다

## 5. SQLAlchemy 모델 작성과 Alembic 마이그레이션 (담당: 장성은)

- **SQLAlchemy ORM** : SQL을 직접 쓰지 않고 파이썬 클래스로 테이블을 다루는 도구 (클래스 1개 = 테이블 1개)
- **Alembic** : 모델에 바뀐 내용을 실제 DB 테이블에 반영해주는 도구. 바뀐 기록을 파일로 남겨서 되돌리기도 가능

### 5-1. 모델 작성 방법

**① Base 상속 + Mixin 활용**

`app/models/` 아래에 테이블마다 파일을 하나씩 만든다.
```python
# app/models/patients.py 예시
from sqlalchemy import BigInteger, String, SmallInteger
from sqlalchemy.orm import Mapped, mapped_column

from app.core.db.databases import Base
from app.core.db.models import TimestampMixin


class Patient(Base, TimestampMixin):
    __tablename__ = "patients"

    id: Mapped[int] = mapped_column(BigInteger, primary_key=True, autoincrement=True)
    name: Mapped[str] = mapped_column(String(30), nullable=False)
    age: Mapped[int] = mapped_column(SmallInteger, nullable=False)
    phone: Mapped[str] = mapped_column(String(11), nullable=False)
```
- `__tablename__` : 실제 DB 테이블 이름
- `Mapped[타입]` : 파이썬에서 쓸 타입 / `mapped_column(...)` : DB 컬럼 설정
- `nullable=False` : 빈 값 불가 (ERD의 NN)
- 다른 테이블을 가리킬 땐 `ForeignKey("patients.id")`

**② 공통 컬럼 Mixin (`app/core/db/models.py`)**

여러 테이블에 똑같이 들어가는 컬럼을 미리 만들어둔 클래스
- `TimestampMixin` : `created_at`(생성 시간), `updated_at`(수정 시간) 자동 기록
- `SoftDeleteMixin` : 실제로 지우지 않고 `is_deleted`로 삭제 표시
- `UUIDMixin` : id를 숫자 대신 UUID로 쓸 때
- `class Patient(Base, TimestampMixin)`처럼 같이 상속하면 그 컬럼이 자동으로 들어간다

**③ `app/models/__init__.py`에 import (중요)**
```python
from app.models.users import User
from app.models.patients import Patient
...
```
- `alembic/env.py`의 `from app import models`가 이 파일을 불러온다
- 여기에 import하지 않으면 alembic이 그 모델을 몰라서 테이블이 만들어지지 않는다

### 5-2. 마이그레이션 방법

**① alembic 설정 (`alembic/env.py`)**
- `config.set_main_option("sqlalchemy.url", DATABASE_URL)` : DB 주소를 `databases.py`에서 가져온다. 그래서 `alembic.ini`의 `sqlalchemy.url`은 주석 처리돼 있다
- `target_metadata = Base.metadata` : 모델 정보를 alembic에 알려준다
- 비동기 엔진(`async_engine_from_config`)으로 연결해서 마이그레이션을 실행한다

**② 실행 순서**
- uv를 쓰지 않을 때는 가상환경을 켠 상태에서 앞의 `uv run`을 빼고 실행한다 (예: `alembic upgrade head`)
1. `.env.example`을 복사해서 `.env` 만들기 (DB 접속 정보)
2. MySQL 켜기
```bash
   docker compose up -d mysql
```
3. 마이그레이션 파일 만들기 (모델과 DB를 비교해서 바뀐 점을 코드로 만들어줌)
```bash
   uv run alembic revision --autogenerate -m "create tables"
```
   → `alembic/versions/`에 파일이 생긴다. 열어서 테이블이 제대로 잡혔는지 확인
4. DB에 반영
```bash
   uv run alembic upgrade head
```
5. DB Viewer(DBeaver, MySQL Workbench 등)로 테이블이 생겼는지 확인
6. 바로 전 상태로 되돌리기
```bash
   uv run alembic downgrade -1
```

**③ 기억할 것**
- 모델을 고치면 `revision` → `upgrade`를 다시 한다
- `alembic/versions/`의 파일은 지우지 말고 같이 커밋한다 (팀원도 같은 순서로 DB를 맞춰야 해서)
